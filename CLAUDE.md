# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Argonaut is a cross-platform (Linux, Windows, macOS) desktop file manager written in C++17 with Qt 6 Widgets. It has to keep working on all three platforms, so use Qt APIs (`QStorageInfo`, `QStandardPaths`, `QDesktopServices`, `QFile::moveToTrash`, etc.) instead of OS-specific calls. Where OS-specific behaviour is unavoidable, put it behind `Q_OS_LINUX` / `Q_OS_WIN` / `Q_OS_MACOS` guards, as `MainWindow::populateSidebar()` does.

The minimum Qt version is **6.4** (what Ubuntu 24.04 ships). Don't use APIs added after 6.4 unless you also raise `find_package(Qt6 6.4 ...)` in `CMakeLists.txt`.

License: GPL-3.0-or-later (`LICENSE`), copyright johngiannop. Hosted at https://github.com/jgiannop/argonaut (`origin`). `.github/workflows/ci.yml` builds and runs the tests on Ubuntu 24.04 for every push and PR; pushing a tag `vX.Y.Z` that matches `project(argonaut VERSION …)` runs `release.yml`, which builds the .deb and publishes a GitHub Release with it. A `.deb` comes from CPack: `cmake --preset package` (Release, prefix `/usr`, no tests), `cmake --build build/package`, `cpack --config build/package/CPackConfig.cmake`. Library dependencies come from dpkg-shlibdeps (so a package built on Ubuntu 24.04 needs 24.04's t64 libraries); optional helpers are `CPACK_DEBIAN_PACKAGE_RECOMMENDS`.

## Build and run

CMake presets (`CMakePresets.json`) use the Ninja generator and build into `build/<preset>`:

```bash
cmake --preset debug            # configure (or: --preset release)
cmake --build build/debug       # build
./build/debug/argonaut [path]  # run; optional start folder (path or file:// URL)
```

In VS Code, CMake Tools is set to use the presets. F7 builds and F5 debugs with gdb (`.vscode/launch.json` runs the `CMake: build` task first).

Linux dependencies: `cmake ninja-build qt6-base-dev qt6-tools-dev designer-qt6 qt6-wayland libvterm-dev libarchive-dev`. `libarchive-dev` is optional too ("Compress / Extract: disabled"; `src/FileJobArchive.cpp` is then left out, `ARGONAUT_ARCHIVES` undefined, `FileJob::archivesSupported()` returns false and the UI hides the actions, and `tst_archives` isn't built). `libvterm-dev` is optional: without it, CMake prints "Embedded terminal: disabled" and the app builds without the terminal panel, with all terminal code behind `#if defined(ARGONAUT_TERMINAL)`. If you add the terminal sources to a stale build directory and the linker reports missing `TerminalWidget` vtable/metaObject symbols, delete `build/debug/argonaut_autogen` and rebuild.

Tests (Qt Test + CTest, in `tests/`). They run headless and sandbox `HOME` and the trash. **`ARGONAUT_TRASH_HOME_ONLY=1` must be set for anything that runs trash code in tests:** without it, `Trash::filesDirs()` also finds the `.Trash-<uid>` folders on real mounted drives, and Empty Trash would delete them. `tst_fileoperations` sets it in `main()` and `tests/CMakeLists.txt` sets it for ctest. Tests also point `HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` at a temporary folder (and `tst_thumbnailer` sets `XDG_DATA_DIRS` to fake thumbnailers), so the real bookmarks file and settings are never touched. Window-level test programs set `ARGONAUT_EJECT_PROGRAM` and `ARGONAUT_GIO_PROGRAM` to fake scripts, so they never eject a real drive, launch real apps, or change default apps.

```bash
ctest --preset debug                                    # all tests
./build/debug/tests/tst_fileoperations copyFolderTree   # one test function
```

In VS Code, CMake Tools' Testing panel runs them too. Formatting: `.clang-format` (Qt-like). Format-on-save applies to changed lines only. There is no linter.

## Architecture

- `qt_standard_project_setup()` turns on AUTOMOC/AUTOUIC. Every new source or header must be listed in `CMakeLists.txt`, or moc won't run on it. The GUI goes in `qt_add_executable(argonaut ...)`. The folder model (`DirectoryModel`), the disk-usage tree (`DiskUsageModel`), the Trash, bookmark and Open With helpers (`Trash`, `Bookmarks`, `OpenWith`) and the file-operations engine (`FileJob`, `FileOperations`, plus `FileJobArchive.cpp` when libarchive is found) are the static library `argonaut_core`, which both the app and `tests/` link against. Keep it free of window/widget code so it stays testable.
- Real file types (`src/ContentType.{h,cpp}`, in `argonaut_core`): this is deliberately **stricter than Nautilus/GIO**, which trust any extension only one type uses.
  - `inspect()` reads the first 4 KiB and calls `judge(byName, byContent)`. The verdicts are Consistent, Identified (no usable name), Mismatch, and Dangerous (`isProgram(content)` while the name isn't a program).
  - Rules that prevent false alarms:
    - Generic or empty content (`application/octet-stream`, `x-zerosize`) is never a mismatch.
    - Related types (`inherits`, e.g. docx is a zip) agree with each other.
    - Two text types never count as a mismatch, because sniffing can't tell Markdown from Python.
  - A read-only scan of a real 749-file Downloads folder gave 0 false alarms and caught 1 real mismatch.
  - `DirectoryModel` applies cached verdicts while listing (`applyCachedContent`) and reads the rest on `m_contentPool` (1 thread). Reading starts only **after** the listing is done, so it never competes with it.
  - On local disks every file is checked; on removable and network drives (`m_thorough == false`) only files whose data the views ask for, i.e. the visible ones.
  - Results go to `ContentType::Cache`: QDataStream at `QStandardPaths::CacheLocation/content-types.bin`, keyed by path, size and mtime, at most 200k entries, saved 3 s after changes and on quit.
  - The effective type (`mimeFor`) is the content type for Identified, Mismatch and Dangerous. `nameMimeFor` is the name-only type. The roles are `VerdictRole`, `NameMimeRole`, `ContentMimeRole` and `Qt::ToolTipRole`.
  - UI: `FileItemDelegate::paintContentBadge` (amber for Mismatch, red for Dangerous).
    - `MainWindow::openFile` warns about Dangerous files and never runs them, and opens Mismatch/Identified files with the default app for the real type.
    - `fixExtension` ("Rename to …") is undoable, and Properties shows "Name says" against the real type.
  - Tests set `XDG_CACHE_HOME`; `ContentType::readCount()` lets them prove that a second visit reads nothing.
- Performance guards in `DirectoryModel`: each batch of a big listing is sorted on its own and **merged** (`resort(sortedPrefix)`), not re-sorted in full. `m_rowByPath` is rebuilt lazily (`rebuildIndex()` only marks it stale; readers call `ensureIndex()`). `FileEntry::fullPath` is built once (`setDir`). Re-run the A/B benchmark if you touch these (`tst_directorymodel bigFolder`, release build): 20,000 files should load fully in about 0.14 s.
  - `makeEntry` does **one `lstat` per file** (plus a `stat` for symlinks) on Unix, not `QFileInfo`. `QFileInfo::lastModified()` converts to local time, and glibc stats `/etc/localtime` twice per call, which tripled a listing's system calls (0.20 s → 0.14 s when removed). Don't call `lastModified()` or `isWritable()` (one `access()` each) per file while listing; check with `strace -c`.
- Sizes: always use `formatSize()` (`src/Format.h`). It gives powers of 1000 with kB/MB/GB, like GNOME and drive labels; never call `QLocale::formattedDataSize`'s default, which gives KiB/MiB.
- Natural name order uses `QCollator` in numeric mode. In the "C"/POSIX locale Qt can't do numeric collation, so `naturalCollator()` uses English rules there; keep that, or `LANG=C` users get "file10" before "file2".
- The look copies GNOME Files (Nautilus) / libadwaita, but it's built only from Qt, so it looks the same on every platform:
  - `Theme` (`src/Theme.{h,cpp}`) holds the light and dark colour tokens, chosen from `QApplication::palette()`. Use the application palette, not the widget palette: our own style sheet changes widget palettes.
  - `glyphIcon(Glyph, color)` draws every UI icon in code through a custom `QIconEngine`. Don't depend on the system icon theme or the Qt SVG plugin for UI icons. File-type icons come from the OS through `QFileIconProvider` (cached per mime type by `DirectoryModel`).
  - Themes (`ThemeMode`: Follow System, Light, Dark, Midnight Blue, Rosé Dawn, Forest, Sunset) are chosen in `PreferencesDialog` and saved with `QSettings` under `appearance/theme` (keys are in `kThemes` in `Theme.cpp`).
    - Light and Dark use libadwaita's exact colours (`adwaita()`). The named themes are built by `custom()` from four base colours (window, sidebar, text, accent), and every other token is derived from those.
    - `applyThemeMode()` sets `QApplication`'s palette (`paletteFor(theme)`). Follow System keeps or restores the platform palette that was captured at startup.
    - `currentTheme()` returns the applied tokens. `MainWindow::applyTheme()` re-styles only when `Theme::id` changes.
    - To add a theme: add a `ThemeMode` value, a `kThemes` entry and a case in `Theme::forMode`. Preferences picks it up automatically.
  - `MainWindow::applyTheme()` builds one window-wide style sheet (`styleSheetFor`, using `@token` placeholders) and re-creates every themed icon. It runs again on `ApplicationPaletteChange`. Anything with a themed icon must be updated there.
- Window chrome: on Linux and Windows the window is frameless (client-side decorations). Set `ARGONAUT_NATIVE_DECORATIONS=1` to turn that off; macOS always uses the native frame.
  - Two `HeaderBar`s, one above the sidebar and one above the content, act as the title bar. Dragging empty space calls `startSystemMove`; double-click maximises.
  - Edge resizing is handled by an event filter on the `QWindow` (`MainWindow::eventFilter` → `startSystemResize`).
  - The window buttons only exist when `m_csd` is true. They sit at the right end of the menu bar row (`menuRow`: the `QMenuBar` stretched, then `addWindowButtons`), not in the header bar. `menuRow` carries the bottom border, so it runs under the buttons too.
- Main view:
  - `DirectoryModel` is a flat table model (Name/Size/Type/Modified) of one folder. Don't go back to `QFileSystemModel`, which was ~5x slower on big folders and couldn't keep folders-first natural order.
    - `setPath()` lists the folder on a worker thread, using a generation counter to drop stale results. Big folders arrive in batches (the first after 15 ms). `loaded` fires when the listing is complete.
    - Each entry is stat-ed once while listing, so painting never touches the disk. Mime type, icon and type name are worked out from the name on demand and cached. Symlinks get their target's icon: Qt's provider gives every link a generic link icon, which the per-mime cache would then reuse for real files.
    - Access (`src/Access.{h,cpp}`, core): the same stat keeps the owner/group/other bits (`FileEntry::permissions`, never Qt's "User" bits, which cost an `access()` each), `ownerId`, `groupId` and `brokenLink`.
      - `LockedRole` (`Access::likelyWritable`, in memory) draws 🔒 at the icon's top-left and `SymLinkRole` an arrow at the bottom-left (`FileItemDelegate::paintAccessBadges`). Tooltips add "Read-only (owner: …)" and "Link to …" (readlink only on hover).
      - Owner, Group and Permissions (`-rw-r--r--`; a link shows its target's) are columns 4–6, hidden unless ticked in the list header's right-click menu (`showListHeaderMenu`, saved as `view/listColumns`, applied after `restoreState` by `applyListColumns`, since headers saved before had 4 columns). Names are looked up once per id. View → Sort lists only the first 4 columns.
      - Cut, Move to Trash, Delete, Rename and Move to Other Pane need `canChangeSelection()`: the exact `access(W_OK|X_OK)` on each selected item's folder (once per folder), and in sticky folders like /tmp only your own items. Copy always works. `IN_ATTRIB` makes a chmod update the row.
    - Sorting is done by the model: folders first (even when descending), then the sort column, then natural case-insensitive order (`QCollatorSortKey`). `resort()` keeps persistent indexes.
    - It watches only the open folder: inotify on Linux, so saved files (`IN_CLOSE_WRITE`) update too, and `QFileSystemWatcher` elsewhere. Changes are rescanned (debounced) and applied as minimal row inserts, removes and updates. More than 500 changes trigger a reset instead. `folderGone` fires if the folder disappears.
    - Sub-folder item counts ("12 items") are computed in the background.
    - Expandable folders (Preferences → List View, `view/expandFolders`, like Nautilus): a **flattened tree** in the same flat model, so selection, actions, drag and drop and rename work unchanged. `setTreeEnabled` / `isTreeActive()` (plain folders only: search, Trash, Recent and Starred stay flat; the grid turns it off via `setGridMode`). `expand(folder)` adds the folder to `m_dirs` and `m_expanded`, watches it (`addWatch`) and lists **only that folder** (`startChildScan` → `applyChildren`, inserted as one block right below it). `collapse` removes the block and every folder opened inside it. `sortTree()` sorts each folder's rows on their own and lays them out depth first; the batch merge in `resort(prefix)` is skipped while folders are open. Depth isn't stored: `depthOf()` counts the levels below `m_path`.
      - `applyRescan(…, scanned)` only touches rows of folders that listing read, so a rescan already running can't drop a folder opened meanwhile; opened folders that vanish are closed. `relist()` (new folder or search) closes everything. Hiding hidden files closes opened hidden folders.
      - Roles: `TreeDepthRole` (-1 = no tree), `ExpandedRole`, `ExpandableRole` (no arrow for "0 items"). `FileItemDelegate::treeIndent` / `expanderRect` place the ▸ arrow and indent the icon, name and rename field. `MainWindow::eventFilter` toggles on a click on the arrow (consumed, so it doesn't select or open), `handleTreeKey`: → opens, ← closes or goes to the parent folder.
    - Invariant: `m_rowByName` is rebuilt **before** `endInsertRows`/`endRemoveRows`, because listeners such as paste-highlight call `indexForPath` from those signals.
  - There are two views in a `QStackedWidget`: `m_iconView` (QListView, IconMode) for the grid and `m_detailView` (QTreeView with columns and sortable headers) for the list. They share the proxy model and **one selection model**. `m_view` points at the visible one.
    - Each view has its own `FileItemDelegate` (grid / list), because delegates cache sizes.
    - The table selects whole rows, so use `selectedViewIndexes()` (column 0 only) instead of `selectedIndexes()`.
    - Overlays (floating bar, progress card, toast) are children of `m_viewStack`.
  - `FileItemDelegate` paints every item itself: wrapped, middle-elided names, rounded hover/selection, list-mode size/date.
    - Zoom: `setIconSize(px)` from the levels `gridSizes()` (32…256) / `listSizes()` (16…48). It clears the wrap cache (keyed by name only) and the thumbnail cache, and emits `sizeHintChanged`, so views re-lay out without a reset and keep the selection.
    - `MainWindow::zoom(+1/-1/0)` / `applyZoom()` also update `m_iconView->setGridSize` and the zoom actions' limits. Ctrl+wheel on a file viewport adds up `angleDelta` and zooms per whole notch (touchpads). Saved as pixels in `view/gridIconSize` / `view/listIconSize`. Thumbnails are kept at up to 256 px (`Thumbnailer::MaxSize`).
  - `Thumbnailer` (in `argonaut_core`) loads thumbnails in a thread pool and emits `thumbnailReady`, which repaints the viewport. Requests come only from `FileItemDelegate::paintIcon`, i.e. visible items, with the **effective** mime (never for Dangerous files). Order: the freedesktop cache (`~/.cache/thumbnails/{large,x-large,normal,xx-large}`, checked against `Thumb::MTime`), then `QImageReader` for images, then on Linux a system thumbnailer.
    - Thumbnailers: `/usr/share/thumbnailers/*.thumbnailer` from every XDG data dir (first per type wins; TryExec must exist). Parsed by `readThumbnailerEntry`, **not QSettings**: QSettings treats `;` as a comment and would keep only the first MimeType. Exec placeholders: `%s` (256, `GenerateSize`), `%u`, `%i`, `%o`, `%%`.
    - They run on `m_external` (2 threads, `nice 10`, LIFO via a rising priority so the newest painted item goes first, 15 s timeout). `MainWindow::navigateTo` calls `cancelPending()`, which drops queued runs.
    - **Sandbox**: when `bwrap` exists, each run gets read-only `/usr`, `/etc`, font and GStreamer caches, `--unshare-all` (no network), its own `/tmp`, and only the one file, bound as `/tmp/gnome-desktop-file-to-thumbnail.<real suffix>` with output `/tmp/gnome-desktop-thumbnailer.png`. Those names matter: Ubuntu's AppArmor profiles (e.g. evince-thumbnailer) only allow these paths. `ARGONAUT_THUMBNAIL_SANDBOX=0` turns it off (tests with fake thumbnailers outside /usr).
    - Results are saved per the spec (PNG with `Thumb::URI`/`Thumb::MTime`/`Thumb::Size`, 0600, atomic rename) into `large/`, shared with Nautilus. Failures get a marker in `fail/argonaut/` until the file's mtime changes.
    - Policy (`thumbnails/generate`, Preferences): local disks only (default; not `needsSafeWrites` or `isNetworkFilesystem`, cached per folder), everywhere, or never (existing thumbnails only).
    - Measured: PDF ~60 ms, video ~140 ms per file in the sandbox. `tst_thumbnailer` covers parsing, caching, failure markers, policies and cancel with a fake thumbnailer, plus real sandboxed evince/totem runs when installed.
  - The views show `DirectoryModel` through `FileFilterProxy` (a `QSortFilterProxyModel`). Indexes from the view or selection are **proxy** indexes: convert them with `toSource()` / `toView()` before calling `m_model->filePath`/`isDir`/etc. `FileItemDelegate` resolves through proxies itself.
  - Search (Ctrl+F) is done by the model, in sub-folders too: `DirectoryModel::setSearch(query)` re-lists (`relist()`) with the worker walking breadth-first from `m_path` and keeping only names that contain **all** words, ignoring case and accents (`foldForSearch`: NFD, drop non-spacing marks, case-fold; ASCII fast path in `matchesSearch`). So Greek "θαλασσα" finds "Θάλασσα".
    - The walk doesn't follow symlinks, stays on the starting drive (`st_dev`, so no `/proc` or mounted sticks) and skips hidden folders unless hidden files are shown (`setShowHidden` searches again). It stops at `MaxSearchResults` (10,000; `searchTruncated()`). In the Trash it only filters, without recursing.
    - Rows are keyed by full path, as in trash mode. The Type column becomes Location (`searchLocation`: relative to the searched folder), and the tooltip says "In …" for the grid. Content checks only read visible results (`m_thorough = false`).
    - Only the searched folder is watched, so `onJobFinished` calls `refresh()` in search mode; the rescan is another full search applied as a minimal diff.
    - `MainWindow` debounces typing by 150 ms (`m_searchTimer`); clearing is immediate. `setPath()` ends a search, and `navigateTo` blocks the search field's signals while leaving search, so the old folder isn't listed again. The floating bar shows "Searching… / N results / No results"; "Open Item Location" goes to a result's folder and selects it.
    - `FileFilterProxy` no longer filters. It never sorts either: `FileFilterProxy::sort` forwards to the model, so header clicks and View → Sort Files both sort `DirectoryModel`. Hidden files are filtered by the model (`setShowHidden`).
    - Read-only benchmark on a real home folder: same results as `find`, first results after ~17 ms, full walk ~2 s warm (`find`: 4.4 s).
- Split view (F3, `setSplitView`): one or two file panes in `m_paneSplitter`. **Every pane-specific member (`m_model`, `m_proxy`, `m_view`, `m_iconView`, `m_detailView`, `m_viewStack`, both delegates, `m_floatingBar`, `m_message(Timer)`, `m_current`, history, `m_grid`, zoom levels, pending selection/scroll/rename, Recent's sort) belongs to the active pane.** `Pane` (`m_panes[2]`) stores each pane's copy; `savePane`/`loadPane` swap them.
  - `activatePane(i)` switches for good: it ends rename, search, Quick Look and Analyze, then `refreshChrome()` (path bar, title, sidebar, actions, view-mode buttons, captions). Input in the other pane (press, key, wheel, focus, context menu) activates it in `eventFilter`, *before* the normal handling, so shortcuts like Delete always act on the pane you're in.
  - `PaneScope(this, i)` switches only temporarily, with `m_background > 0`, for things that happen in a pane that isn't active: its model loading, selection changing or folder vanishing (every connection made in `buildPane` captures the pane index), drags and drops onto it, its resize. While `m_background`, the shared chrome isn't touched (`updateActions`, `updateEditActions`, `updateBookmarkAction`, `syncSidebarSelection`, `updateSortActions`, `updateViewChrome` and `refreshChrome` return early).
  - `buildPane(parent, index)` makes everything a pane needs; the second pane is built on first use (`ensureSecondPane`) and starts in the first pane's folder. Tabs (and the Toast/OperationsPanel overlays) belong to the first pane: tab functions call `activatePane(0)` first. So does Analyze.
  - `onJobFinished` highlights results and refreshes searches **in every pane** (that's how F5's copies are selected in the other pane). `applyTheme` restyles both panes' delegates. Drag auto-scroll uses `m_dragScrollView`, the pane being dragged over.
  - F5/F6 (`transferToOtherPane`) copy or move through `FileOperations`, so they get progress, conflicts, undo and USB safety. They're enabled only if the other pane is a real, writable folder (not Recent/Starred/Trash). `fitListColumns()` hides Type below 640 px and Modified below 460 px, so names keep room in a narrow pane. Saved: `view/split`, `view/splitPath`.
  - Tested by the window harness `splittest`, including "Delete in one pane never touches the other's selection".
- Quick Look (Space): `QuickLook` (a `Qt::Tool` window shown without activation, so the file view keeps the keyboard) shows `Preview::load()` results (core, `src/Preview.{h,cpp}`), loaded on `QThreadPool::globalInstance()` and dropped if a newer item was asked for.
  - The kinds: Image (`QImageReader` by content, decoded at the window's size; `QMovie` for animations); Text (first 200 kB, not if it has NUL bytes; `isTextual` by mime inheritance); Archive (`FileJob::listArchive`, libarchive headers only); Folder (item count); Blocked (Dangerous files, decided **before** anything opens the file); Generic. Anything else with a system thumbnailer goes through `Thumbnailer::render(path, mime, size)`, the same sandboxed run at preview size and not cached.
  - Space is handled in `eventFilter` after type-ahead (`typeAheadKey` keeps a space that's part of a typed name), so `m_previewAct` only shows "Space" in menus (`Qt::WidgetShortcut`, not added to the window). The preview follows the selection model's `currentChanged`; its own arrow keys are re-sent to the view (`navigate`). It closes on folder change, entering Analyze and switching panes.
- `navigateTo(path, addToHistory)` is the **only** way to change the current folder. It validates and cleans the path into `m_current` (always with `/` separators; the native form is only for display), leaves search mode, and updates history, `PathBar`, the title, the sidebar selection and the floating bar. Everything that changes folder goes through it: actions, sidebar, breadcrumbs, the typed path, double-click and the command-line argument.
- `PathBar` shows breadcrumbs. Leading crumbs are hidden when space is short, and it switches to a `QLineEdit` on a click (press **and release**) or Ctrl+L; dragging its free space or a crumb moves the window, like the rest of the header (crumbs: an event filter, `setDown(false)` before `startSystemMove`, so no click follows). It emits `pathActivated`.
- Sidebar entries are `QListWidgetItem`s with the path in `PathRole` (`Qt::UserRole`). Separator rows have `SeparatorRole` and an empty path.
- File operations (copy, cut/paste, move to trash, undo):
  - `FileJob` runs one operation on a worker thread (`FileOperations` owns a 2-thread pool). It first measures the total size, then transfers chunk by chunk, checking `cancel()`. Progress is a mutex-guarded snapshot (`progress()`); `progressChanged` is throttled and delivered queued.
  - Safety rules to keep:
    - Never overwrite: files open with `QIODevice::NewOnly`. When the destination name is taken, `transferItem` resolves the clash:
      - Copies into the item's own folder duplicate without asking.
      - Otherwise `askUser` emits `conflict(source, existing)` and the worker **waits** (`QWaitCondition`) until `resolveConflict()` or `cancel()`.
      - The answers are Replace (the existing item goes to the **Trash** first; it is never deleted), Skip, KeepBoth (`uniqueTargetPath` or a typed name), Merge (folder onto folder: `mergeInto` handles each child, asking again inside) and Cancel.
      - "Apply to all" is remembered separately for files and folders.
      - Only newly created items go into `results`, so undoing a merge never touches what was already there.
      - Jobs ask only when `FileOperations::setAskOnConflict(true)`; otherwise they keep both silently, which is the tests' default. `MainWindow` shows `ConflictDialog`s one at a time (`m_conflicts` queue).
    - A move tries `QDir::rename` first and falls back to copy and then delete; the original is deleted only after the copy is complete.
    - A cancelled or failed item removes only its own newly created target.
    - Removable drives (`needsSafeWrites`): on Linux these are udisks mounts under `/media` or `/run/media`, a USB sysfs path, or the sysfs `removable` flag; on macOS, `/Volumes/`. For those, data is flushed to the device every 32 MiB (`fdatasync`). The filesystem is synced (`syncfs`) before a cross-filesystem move deletes the source, and again at the end of the job. During that final sync the job shows `Progress::finishing` ("Writing to the drive…"), and the drive is listed in `flushedDrives()`. The internal disk is never synced, to keep it fast. `ARGONAUT_SAFE_WRITES=1/0` forces the behaviour (used by the tests).
  - `FileOperations` records each user action's `TransferResult`s on an undo stack. Undo runs the inverse job: a copy is undone by trashing the copies (never deleting them), a move by moving back, and a trash by `Restore`, which also removes the Linux `.trashinfo`.
    - Redo: `runInverse()` serves both directions. An entry stores the job that happened (`kind`, `results`) plus the user's original `action`/`name` for the menu text. When the inverse job finishes, *its* results become an entry on the other list. So redoing a copy restores the very copies the undo trashed (Restore's inverse is Trash), a move moves again, and a trash trashes again.
    - Any new action (`startJob` with `recordUndo`, or `recordUndo()`) clears `m_redo`. `recordUndo(kind, results, action)` takes a name ("Rename", "New Folder") and builds "Undo …"/"Redo …".
    - History jobs carry `HistoryProperty` ("undo"/"redo") so `onJobFinished` says "Undone"/"Redone".
  - Undo jobs are marked with the `UserActionProperty` dynamic property set to false, so `MainWindow::onJobFinished` treats them differently.
  - The clipboard uses `text/uri-list` plus the GNOME (`x-special/gnome-copied-files`), KDE (cut flag) and Windows ("Preferred DropEffect") formats, so it works with other file managers.
  - UI: `OperationsPanel` (bottom-left card) appears only for jobs running longer than 400 ms. `Toast` (bottom-centre, with an Undo button for trash) avoids the panel's rectangle.
- Archives (`src/FileJobArchive.cpp`, libarchive; `FileJob::Kind::Extract` / `Compress`, so they get the job engine's progress, cancel, USB safety and undo):
  - Extract unpacks each archive into a hidden `dest/.<base>.argonaut-extract` folder, then places it: exactly one top-level item is renamed out as is, otherwise the temporary folder becomes `<base>` (both via `uniqueTargetPath`, never overwriting). Cancel or failure removes the temporary folder.
  - Security: `isUnsafePath()` rejects absolute, `..` and drive-letter paths (and hardlink targets) and counts them in one warning; `ARCHIVE_EXTRACT_SECURE_SYMLINKS | SECURE_NODOTDOT` also apply. **Not** `SECURE_NOABSOLUTEPATHS`: every entry is rewritten to an absolute path inside the temporary folder.
  - `support_format_raw` handles plain `.gz`/`.xz`; the entry is named after the archive (`archiveBaseName`, which knows `.tar.gz` and friends). Progress is compressed bytes read (`archive_filter_bytes(a, -1)`). Encrypted archives give an error (no password support yet).
  - Compress writes all sources into `dir/.<name>.argonaut-part` and renames it when complete. The format (`ArchiveFormat`: zip with UTF-8 names, tar.gz / tar.xz as pax_restricted, 7z) goes through `FileOperations::m_pendingFormat` → `setArchiveFormat` before the job starts.
  - Undo of either trashes what was created (like Copy). `MainWindow::selectedArchives()` decides by the **effective** mime (`FileOperations::isArchive`), refusing Dangerous files. `CompressDialog` remembers the format in `archive/format`.
  - `tst_archives` covers round trips in every format, zip-slip/absolute/symlink escapes, placement, cancel (20k-entry tar, cancelled with a `DirectConnection` so it's deterministic), damaged archives and undo.
- Drag and drop:
  - Drags start in the views; `DirectoryModel::mimeData` gives one URL per item, plus text paths.
  - Drops are **not** handled by Qt's view/model logic. `eventFilter` intercepts DragEnter/Move/Leave/Drop on the views' viewports (`handleViewDrag`) and on the sidebar (`handleSidebarDrag`). The viewports have `setAcceptDrops(true)` explicitly, otherwise Qt delivers drag events to the view instead.
  - The target is the folder under the cursor (highlighted through `FileItemDelegate::setDropTarget`), otherwise the open folder.
  - `dropActionFor` decides like Nautilus: same device (cached `QStorageInfo::device`) moves, another device copies, Ctrl copies, Shift moves. It refuses drops into the item itself, drops where the items already are, and drops into read-only folders.
  - Drops go through `FileOperations`, so they get progress, undo and USB safety.
- Analyze view (Ctrl+3, `m_analyzeAct` in the view action group, header button `m_analyzeButton`): `m_analyzeView` (a `QTreeView`, third page of `m_viewStack`) over `DiskUsageModel`, with `UsageDelegate` painting the usage bar.
  - It is **never** `m_view`, and it has its own model and selection. While `m_analyzing`, `selectedViewIndexes()` returns nothing and `updateEditActions` disables file actions, so window shortcuts (Delete, Ctrl+A…) can't act on the hidden file view's selection. Delete in the tree is a widget-scoped action on `m_analyzeView`.
  - `DiskUsageModel` (core): a tree of `Node`s. `Node::Kind` is Folder, File or SmallerFiles. `bytes` includes the item's own entry and everything inside; `items` counts entries at any depth. The one top-level row is the shown folder (`m_root`).
    - Each folder keeps its sub-folders (`children`), its biggest files (`files`: at most `MaxFilesPerFolder` = 10 of at least `MinFileBytes` = 256 kB, so memory stays small: ~94 MB peak for a 1.6 M-item home) and `smallerBytes`/`smallerCount` for the rest. With `setShowFiles(true)` the rest is one "N smaller files" row (`smaller`, made on demand, always sorted last), so a folder's rows add up to its size.
    - View rows are **built lazily**: `ensureRows()` fills `Node::rows` (sorted) and each `Node::row` the first time a folder is asked for. `relayout()` drops all row lists and remaps persistent indexes by `Node*`, so sorting and size changes keep the view's expanded folders and selection; it never resets the model.
    - The worker (POSIX `open`/`fdopendir`/`fstatat`, `QDirIterator` elsewhere) reads a folder fully before recursing, so only one fd is open at a time. It counts `st_blocks * 512`, counts hard links once (`(dev, ino)` set), never follows symlinks and never enters another `st_dev`. **Result: byte-for-byte equal to `du -sxB1`** (tests compare with `du`; ~4.7 s for a 437 GB, 1.6 M-item home vs `du` 4.4 s).
    - Each top-level sub-folder is sent, fully measured, as a raw `Node*` (`addTopChild`) and inserted at its sorted position. A generation counter drops results from an older scan.
    - `setRoot()` re-roots without scanning when the path is inside a complete scan (navigating in and up within it is instant). `navigateTo` calls it while analyzing. `onJobFinished` keeps the tree in sync without a rescan: `removePath()` for Trash/Move/Delete sources (subtracting up the tree), `addPath()` for Copy/Move/Restore (so Undo of a trash)/Extract/Compress targets, which measures just that item on the worker and adds it (`added` signal). Small files aren't nodes, so Trash/Move pass `sizeOnDisk(target)` (measured where the item went) to correct the "smaller files" totals. Nothing is watched: "Scan Again" (`rescan`) for changes from other programs.
    - "Show Files When Analyzing" (`m_analyzeFilesAct`, saved as `view/analyzeFiles`): `setAnalyzeShowFiles` saves and restores the expanded folders around the model reset. File rows open with `openFile` (real-type checks) and offer Show in Folder.
    - Activating a row navigates to that folder (still analyzing). Ctrl+F or Ctrl+1/2 go back to the file view. The floating bar shows "Measuring… / total / selected share".
- Embedded terminal (`TerminalWidget`, Unix only): a bottom panel in `m_contentSplitter` under the file views. Ctrl+` toggles it; it is also in View → Terminal, the header button and the context menu's "Open in Terminal".

The exceptions are `setPassthroughShortcuts` (the toggle). `focusNextPrevChild` returns false so Tab reaches the shell, and composed text arrives through `inputMethodEvent`.

- Trash (Linux/BSD, freedesktop spec; `src/Trash.{h,cpp}`):

In trash mode the Type and Modified columns become Original Location and Deleted.

- Recent and Starred are **places, not folders**: `navigateTo` accepts `DirectoryModel::recentPath()` (`recent:///`) and `starredPath()` (`starred:///`) without the folder checks, and `m_current` holds that string.

Only items that still exist are shown. Rows are keyed by full path; the Type column is Location (`~/…`), and Recent's Modified column is "Last Used" (`FileEntry::used`). Recent isn't folders-first. It watches the folder of the list's file and rescans when it changes.

Writable checks fail on these paths, so Paste and New Folder are off. Analyze and Bookmark are disabled. `showTerminal` uses home. The path bar and title show the place's name.

It **never writes a file it couldn't parse**. `add` is a no-op when GNOME's `remember-recent-files` is off (`ARGONAUT_REMEMBER_RECENT=0/1` overrides it in tests). `MainWindow::rememberOpened` is called by `openFile` (not for Dangerous files) and by Open With. GTK's `RecentManager` reads what we write (checked).

The folder is created only on first save. `renamed(from, to)` moves stars, including those inside folders; `onJobFinished` calls it for Move results (so undo/redo too), as do both rename paths. Missing items stay starred but hidden. `DirectoryModel::StarredRole`; `FileItemDelegate::paintStarBadge` draws ★ at the icon's top-right.

- Sidebar sections: Recent, Starred and places + Trash, then bookmarks, then drives. Rows carry `PathRole`, `KindRole` (`PlaceItem`, `BookmarkItem` or `DriveItem`) and `EjectRole`. `populateSidebar()` rebuilds everything; `scheduleSidebarRefresh()` debounces it.

It refuses while a job uses the drive, and leaves the drive first if it's the open folder.

- Tabs share the **one** view and model. `m_tabs[i]` (`TabState`) stores a tab's folder, back/forward stacks, selected paths and scroll position.

- Install and default file manager (Linux):
  - `cmake --install` (the release preset's prefix is `~/.local`) installs the binary, `argonaut.desktop` (from `data/argonaut.desktop.in`, with the **absolute** binary path because D-Bus and the shell don't use the user's PATH) and `data/argonaut.svg`.     - **It stays running while Argonaut is the default.** Nautilus asks for `FileManager1` whenever it runs (Ubuntu's desktop icons, DING in gnome-shell, start it in the background) and waits in line if it's taken; a service that quit after its last window handed "Show in folder" to Nautilus. So `--service` sets `setQuitOnLastWindowClosed(false)`, asks with `IfTaken::WaitInLine` (`QueueService`; `nameAcquired` when Nautilus lets go), exits at once if another `argonaut --service` owns or waits for the name (`anotherServiceRuns`: `ListQueuedOwners` + `/proc/<pid>/exe`), and quits only when our service file is gone (checked every 10 s) and no window is open.

  - `main()` handles `--make-default` / `--restore-nautilus` **before** creating a QApplication (they work without a display). Positional arguments: folders open (the rest in tabs); files are shown selected in their folder.
  - **`tst_fmservice` runs only under `dbus-run-session`** (ctest sets `ARGONAUT_PRIVATE_BUS=1`) and refuses a bus that has `org.gnome.Shell`: taking the name on the desktop's bus would steal "Show in folder" from Nautilus. - Open/Save windows for other apps (Linux, `ARGONAUT_DBUS`; opt-in): Argonaut is an xdg-desktop-portal **FileChooser backend**.

X11 parents (`x11:<hex>`) become the transient parent. The "Replace?" question runs a nested loop, so it's guarded (`m_chooserAsking`, `QPointer` self): the app's Close can delete the window meanwhile. The service quits after 5 idle minutes.

  - `tst_filechooser` (under `dbus-run-session`) covers decoding with the portal's real wire types, delayed replies, Close, filters and the config switch in a sandboxed XDG tree.

- Git badges (`src/GitStatus.{h,cpp}`, core; `tst_git`): each `DirectoryModel` owns a `GitStatus`. `setFolder` finds the repository (`findRoot`: a `.git` folder or file above, same `st_dev`, not on network drives) and runs `git status --porcelain=v2 --branch -z --ignore-submodules=all --no-optional-locks -c core.fsmonitor=false` under `nice`, killed after `TimeoutMs` (8 s → `tooSlow()`). Keep that check, and never add git commands that read the work tree without it.

- Search inside files (`src/ContentSearch.{h,cpp}`, core; `tst_contentsearch`; toggle "Inside files" / View → Search Inside Files, `search/contents`, `DirectoryModel::setSearchContents`): during the search walk, files whose **name** doesn't match are read if they're text by name (`isTextFile`: inherits text/plain, json, xml, scripts…; ≤ 4 MB; no NUL in the first 4 KiB), only on local disks (`scanText`). Then `gio info <address>` gives the `local path:` to open; none means smb://server/ itself → `MainWindow::chooseShare` (`gio list`, hiding `$` shares).
  - `Remote::mounts()` / `mountOf()` parse GVfs's folder names (`sftp:host=x,user=y`, `smb-share:server=…,share=…`, `dav:…,ssl=true,prefix=…`, `mtp:host=…`) into a name and an address; no process runs. Sidebar: a Network section (connected servers with ⏏ = `Remote::unmount`, network bookmarks from the GTK bookmarks file via `Bookmarks::loadRemote`, and "Connect to Server…" = `connect:///`). The gvfs folder is watched (mounts inside one FUSE mount don't change `/proc/mounts`). `navigateTo` sends any `Remote::isRemoteAddress` to `connectToServer`. PathBar and titles show the server's name. Trash on a server offers Delete Permanently instead.
- Claude (`src/Claude.{h,cpp}`, `src/KeyStore.{h,cpp}`, core; `tst_claude`; Preferences → Claude): no C++ SDK, so `Claude::Client` calls the HTTP API with QNetworkAccessManager (Qt6::Network): `POST /v1/messages`, `POST /v1/messages/count_tokens`, `GET /v1/models` (the **free** key test). Headers `x-api-key`, `anthropic-version: 2026-10-21`. `send()` fills in the model (`claude/model`, default `claude-opus-5-5`; Sonnet 5.5 / Haiku 5.5 selectable), `max_tokens` 16000 (non-streaming) and, for Opus/Sonnet, the server-side fallback (`fallbacks: "default"` + `anthropic-beta: server-side-fallback-2026-07-01`); retries 429/5xx/529 twice (honouring `retry-after`); treats `stop_reason: refusal` as an error. Every response's usage is priced (`Claude::cost`, prices in `models()`) and added to `claude/spent`. `ARGONAUT_CLAUDE_BASE_URL` points tests at a fake server.
  - `claude/mode`: NamesOnly / Ask (default: Claude asks to read the start of some files) / Auto.
  - The key: `ANTHROPIC_API_KEY` wins; else the freedesktop Secret Service over QtDBus (attributes application=argonaut, type=anthropic-api-key; plain session; prompts waited for) — no libsecret needed; else a 0600 file in AppConfigLocation, and the UI says which. `ARGONAUT_KEYSTORE=file` in tests: **never touch the real keyring from tests**.
- Organize with Claude (`src/Organizer.{h,cpp}`, core, `tst_organizer`; `src/OrganizerDialog.{h,cpp}`; File menu and the background context menu; `tests/FakeApi.h` is the shared fake API server):
  - `scan()` lists the folder's top level (no hidden items; at most `MaxItems` = 500, newest first) with the **real** type (`ContentType::inspect`), Dangerous files, project folders (`.git`, `package.json`… inside) and a few names inside sub-folders. The inventory is TSV inside `<inventory>`; tabs and line breaks in names are flattened.
  - Two strict tools, `tool_choice: auto` (forced tool choice is a 400 on Opus 5.5): `read_files` (not offered in NamesOnly mode or after `MaxReadRounds`; in Ask mode `readRequest` → `allowReading`) and `propose_plan` (report in Markdown + moves {item, folder, new_name, reason}). The whole assistant turn, thinking blocks included, is sent back unchanged. The system prompt says names and contents are data, not instructions.
  - `excerpts()`: text (1500 chars), PDFs via `pdftotext -l 2` **only inside bubblewrap** (no sandbox → not read), images as a ≤512 px JPEG `image` block; Dangerous files never.
  - `validate()` rejects unknown items, paths outside the folder, bad names, two items to one place, existing targets, a folder into itself, and moves into a folder the plan also moves. The dialog shows rejected moves in red, unticked.
  - `MainWindow::applyOrganizePlan`: creates the folders (recorded as "New Folders", Copy kind) then one `FileOperations::moveItems(transfers, "Organize")` job with renames, so Ctrl+Z twice restores the folder exactly.
- Sandboxed tools (`src/Sandbox.{h,cpp}`, core): `Sandbox::run(program, args, file)` runs a tool on **one untrusted file** in bubblewrap (read-only /usr and /etc, own /tmp, `--unshare-all`, the file at `/tmp/input.<suffix>`, `@FILE@` in args). No bwrap → the tool isn't run at all. Used by `Organizer` (pdftotext) and `MediaInfo` (exiftool); never run parsers on untrusted files outside it.
- Media details (`src/MediaInfo.{h,cpp}`, core, `tst_mediainfo`): Properties → Details for images, audio, video and PDFs, read on `QThreadPool::globalInstance()` with exiftool `-json` in the sandbox (`fromExifToolJson` maps tags to labelled rows); without exiftool, an image still gets its size from Qt.
- Smaller Nautilus features: **Restore All** (Trash bar and background menu; enabled from `updateEditActions`, which now also runs when a listing loads and when Trash rows change); **spring-loaded folders** (`m_springTimer`, 800 ms over a folder in the view or a sidebar entry → `springOver`: expands in place in the tree, else `navigateTo`; the other pane via `PaneScope`); **Send by Email…** (`xdg-email --attach`, `ARGONAUT_EMAIL_PROGRAM`); **Set as Background** (copies into `$XDG_DATA_HOME/backgrounds`, sets `picture-uri` and `picture-uri-dark` with gsettings, `ARGONAUT_GSETTINGS_PROGRAM`); **Scripts ▸** (`scriptsMenu`: `~/.local/share/nautilus/scripts`, run like Nautilus: cwd = folder, names as args, `NAUTILUS_SCRIPT_*` variables).
- Search filters (`DirectoryModel::setSearchFilters`, `passesFilters`; the "Filters" button): type (by name's mime) and date (mtime). `isSearch()` is true with filters alone, so they search the tree without words; `setSearchActive(false)` clears them.
- There is no status bar. `m_floatingBar` (a `QLabel` over the view) shows selection info and temporary messages (`showMessage`).
